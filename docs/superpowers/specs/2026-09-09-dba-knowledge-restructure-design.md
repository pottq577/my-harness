# DBA 지식 베이스 재구성 설계

## 목표

`raw/` 원문을 변경하지 않고 아직 구조화되지 않은 항목을 `annotated/`에 편입한다. 표현과 서식이 다른 중복도 의미 기준으로 판정해 단일 기준 문서에 연결하며, 색인과 라우팅 문서를 실제 문서 집합과 일치시킨다.

## 원칙

- `raw/`는 출처 계보이며 수정하지 않는다.
- `annotated/`는 실제 검색 대상이다.
- 완전 중복은 새 문서를 만들지 않고 기존 기준 문서에 출처만 추가한다.
- 부분 중복은 기존 문서에 고유 내용을 병합한다.
- 독립 주제는 `DBA-039`부터 순서대로 부여한다.
- DB 설계와 운영 밖의 학습, 면접, 이력서 항목은 `DBA-999` 한 문서로 묶는다.
- 제품 버전, 제한, 가격, 기능 상태처럼 변하는 사실은 공식 문서 확인 시점과 링크를 기록한다.

## 중복과 병합 결정

- `raw/6.md`의 분석 쿼리 항목은 `DBA-038`과 중복이므로 새 문서를 만들지 않는다.
- `raw/7.md`의 Redis Big Key 항목은 `DBA-027`의 축약본이므로 새 문서를 만들지 않는다.
- 정산, 배포 호환성, 배치 시간, SQL과 ORM의 고유 내용은 각각 `DBA-018`, `DBA-023`, `DBA-036`, `DBA-019`에 병합한다.
- Split Brain과 레플리케이션, SQL과 NoSQL의 두 원문, DB 직무 성장 관련 세 원문은 각각 한 문서로 통합한다.

## 완료 조건

- `raw/1.md`부터 `raw/7.md`까지 작업 전후 SHA-256이 같다.
- annotated ID, 파일, 인덱스, 지식 지도, `read_also` 링크가 모두 유효하다.
- 신규 문서가 메타데이터 스키마를 만족하고 실제 질문에서 검색된다.
- 현재성이 필요한 설명은 2026-09-09 기준 공식 자료와 충돌하지 않는다.
