# DBA Knowledge Retrieval Guide

AI가 DBA 지식 문서를 찾아 답변할 때 따르는 과정이다. `knowledge-map.md`로 섹션을 좁히고, `annotated/`의 frontmatter로 문서를 고른 뒤, 최종으로 본문을 읽는다. 최종 답변에는 출처로 문서 ID(`DBA-XXX`)를 달아 준다.

## 조회 흐름

1. 사용자 질문에서 도메인 단어, 기술 용어, 현재성 요구를 분리한다.
2. `knowledge-map.md`의 라우팅 우선순위에 따라 후보 섹션을 고른다.
3. 후보 문서의 `annotated/` frontmatter를 읽고 `triggers`, `code_signals`, `applies_to`가 질문과 맞는지 확인한다.
4. 가장 많이 맞는 문서의 본문을 읽는다. 버전, 가격, 제한, 지원 상태가 답에 필요하면 `verified_at`과 `references`를 확인하고 공식 문서로 다시 검증한다.
5. 답변에 `참고: DBA-030` 같은 출처 표기를 붙인다.

## 라우팅 룰

- 도메인 단어 우선: 결제, 쇼핑몰, 검색, 푸시, 로그인 같은 서비스 단어가 있으면 섹션 11을 먼저 본다.
- 기술 용어로 좁히기: 인덱스, 트랜잭션, ORM, 스키마 변경, 복제, 캐시, 백업 같은 용어로 해당 섹션을 고른다.
- 겹침: 도메인과 기술이 겹치면 주 문서를 고른 뒤 `read_also`로 필요한 문서만 추가한다.
- 성장 질문: 학습, 면접, 이력서 질문은 `DBA-999`를 먼저 읽고 해당 기술 문서로 이어 간다.
- 현재성: 오늘 기준, 최신, 현재 지원 여부를 묻는 질문은 annotated 본문만으로 확정하지 않고 공식 자료를 다시 확인한다.

## 문서 선택 기준

frontmatter 필드를 아래 우선순위로 매칭한다.

1. `triggers`가 질문 문구와 일치하는 문서
2. `code_signals`가 코드 조각에 그대로 보이는 문서
3. `applies_to`가 질문 의도와 일치하는 문서
4. `summary`를 읽고 최종 확인

## 출력 예시

```text
질문: 재고를 동시에 주문하면 중복으로 팔리는 문제를 막으려면?
라우팅: 도메인(쇼핑몰) = 섹션 11 + 기술(락) = 섹션 4
선택: DBA-034, DBA-014
답변: ... 진행
출처: DBA-034, DBA-014
```

## 주의

- 이 스킬 패키지의 문서는 `annotated/` 아래에 있고 frontmatter를 갖는다.
- ID는 `document-index.md` 기준이며 변경하지 않는다.
- `raw/`는 원문 보존과 계보 확인 전용이며 질문의 직접 근거로 사용하지 않는다.
