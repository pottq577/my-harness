# DBA Knowledge Base 스킬

DB 관련 코드 작업과 답변에서 10년차 DBA가 작성한 72개 지식 문서를 판단 근거로 사용한다. 지식 문서는 설계 원칙과 위험을 제공하며, 실제 저장소와 DBMS의 사실을 대신하지 않는다.

## 조회 절차

1. 먼저 현재 저장소의 DBMS, 버전, 스키마, 마이그레이션, SQL, ORM, 설정과 테스트를 확인한다.
2. 작업에서 도메인 단어, 기술 용어, 코드 신호와 현재성 요구를 분리한다.
3. [knowledge-map.md](knowledge-map.md)에서 가장 구체적인 섹션을 고른다.
4. 후보 문서의 `triggers`, `code_signals`, `applies_to`를 비교한다. `rg`로 후보를 좁히고 72개 본문 전체를 한꺼번에 읽지 않는다.
5. 주 문서의 본문을 끝까지 읽는다. 결론에 필요한 경우에만 `read_also` 문서를 추가로 읽는다.
6. 직접 맞는 문서가 없으면 이 지식 베이스에 직접 근거가 없다고 밝힌다. 가까운 문서를 억지로 출처로 삼지 않는다.

## 적용 규칙

- 지식 문서의 원칙을 현재 코드와 운영 조건에 대입한다. 승인된 요구사항과 저장소의 실제 상태가 우선한다.
- MySQL의 DDL, InnoDB 락, PostgreSQL의 MVCC, Redis 명령처럼 엔진에 종속된 예시는 다른 제품에 그대로 옮기지 않는다.
- 버전, 가격, 지원 기능, 제한과 운영 명령은 해당 제품의 현재 공식 문서로 다시 확인한다.
- 문서 근거와 현재 저장소에서 도출한 판단을 구분한다. 둘이 충돌하면 차이를 밝히고 저장소와 공식 문서를 따른다.
- 코드 변경은 요청 범위 안에서 가장 작은 수정으로 수행하고, 해당 프로젝트의 테스트와 검증 규칙을 따른다.

## 출처 계약

- 답변, 구현 설명과 리뷰 결과 끝에 `참고: DBA-XXX` 형식으로 실제 사용한 문서만 적는다.
- 출처 표기를 위해 제품 코드나 마이그레이션에 주석을 추가하지 않는다.
- 질문의 근거는 `annotated/`만 사용한다. `raw/`는 원문 계보 확인용이며 답변 근거가 아니다.
- ID와 파일 매핑은 [document-index.md](document-index.md)를 따른다.
- 문서를 유지보수할 때만 [metadata-schema.md](metadata-schema.md)를 읽고 `annotated/`, 인덱스와 지도를 함께 갱신한다.
